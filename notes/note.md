## 階段 1：看整體（目標：用三句話介紹 LUNA）

**讀**
- 整理 §1（總覽與流程圖）：只讀這一節，先不要管公式。
- 整理 §2.3、§2.4、§2.5：LLM 怎麼逐字生成、為什麼比分類器難分析。
- 整理 §3：三個面向（OOD、對抗、幻覺），每個一句話。

**操作**
- 觀念頁「LLM 做的事：一個迴圈」：看 LLM 怎麼逐字生成，指出「隱藏狀態」在哪裡（01 節開頭有連結）。
- 網頁 01：看「目前如何分析 LLM」的圖與表格，分清楚黑箱評測、探測激活、LUNA 各看什麼；再讀下面三張卡片（Self-attention、規模龐大、生成式輸出）。
- 網頁 02：依序點四個階段，每個階段說出「輸入、輸出」。

**要能說出來**
1. LLM 每寫一個字都有一個隱藏狀態（論文說 Llama-7b 是 32 × 4096 = 131,072 個數字），一個答案是一條狀態路徑。
2. LUNA 把這些狀態壓成一個小的機率狀態機，再給每個狀態貼上「好不好」的分數。
3. 用這個分數去抓異常輸出：幻覺、分布外輸入、對抗攻擊。

**過關檢查**：不看筆記，能畫出「輸入 → 隱藏狀態 → 抽象狀態 → 語意 → 分數 → 判異常」這條流程。

## 階段 2：狀態抽象與 DTMC（03、04 節）

**讀**
- 整理 §4.1～§4.4（為什麼抽象、PCA、Grid／Cluster、轉移抽象、DTMC 定義）。§4.5 HMM 先略讀，只記得「HMM 是兩層抽象、表現比 DTMC 差」。
- 不熟的話先看觀念頁的 PCA、K-Means、GMM、馬可夫鏈。

**操作 03 狀態抽象**
1. 先播「從文字到一個點」動畫：一個 token → 最後一層隱藏狀態 → PCA → 地圖上的一個點。
2. 「劃分探索器」：劃分方法選 Grid，把每維格數從小拉到大：看 `|S̄|` 增加、紅色空洞格出現、SUC 變差。
3. 換成 KMeans：狀態只出現在有資料的地方。
4. 對照右側分數：異常輸入的 COV 應比正常的高。
5. 看下方公式區的 SUC、COV、SEN 三個按鈕，各讀一次公式和作用。

**操作 04 建構 DTMC**
1. 先播「網格 → DTMC 節點 → 一條軌跡」動畫：同一張 5×5 網格，每格是一個抽象狀態，句子的 token 依序跳格。
2. 「轉移模型建構器」：拉「看過軌跡數」，看 P̂ 收斂、`Mean |P̂−P|` 變小（資料越多模型越準）。
3. 點節點建立路徑，或按「典型路徑」「怪異路徑」：看平均轉移機率（也就是 OOD 分數）怎麼變。
4. 拉「真實 LLM 的確定性」：看熵量表上的圓點在「穩定界」與「隨機界」之間移動。
5. 看公式區的轉移機率、路徑分數、SDE。

**要能說出來**
- 抽象就是「降維 + 分群」，把高維連續狀態變成少數離散狀態。
- DTMC 的轉移機率就是「數次數再除以總數」。
- Grid 會有空洞狀態（浪費），Cluster 只在有資料處建立狀態。

**過關檢查**：用 04 的轉移模型建構器示範「為什麼典型路徑分數高、怪異路徑分數低」。

## 階段 3：語意與異常偵測（05、06 節）

**讀**
- 整理 §5（語意綁定，尤其 §5.4 的表：幻覺綁在狀態、OOD 與對抗綁在轉移）。
- 整理 §7.1、§7.2（偵測流程與論文範例：TruthfulQA 的 "denser" 例子，分數 0.04；OOD 的 0.34 對 0.78）。
- 觀念頁「ROC 曲線與 AUC：一步一步建出來」。

**操作 05 語意綁定與逐 token 偵測**
1. 先播「句子分數 → 抽象狀態 → 軌跡分數」動畫：每個句子只有一個分數，廣播給它所有 token，格子的 θ̄ 是落進來的分數平均。
2. 「軌跡檢視器」：切換範例（OOD／HAL、正常／異常）。範例是依規則挑的（分數差最大的幾題 + 一個反例），不是隨機抽樣。
3. 拖門檻：看判定何時從正常變異常、紅框（第一個低於門檻的 token）怎麼移動。
4. 找那個「判錯」的反例，說明為什麼。

**操作 06 從分數到 ROC AUC**
1. 讀上方兩段文字，特別是「標籤從哪來」：作者程式把 `truth_prob` 以 0.5 切成 0／1，θ̄ 其實是 `pos / (pos + neg)`。
2. 「分數分布與 ROC」：任務切換 GPT2-OOD 與 GPT2-TQA，看兩個直方圖分開或重疊、AUC 差多少。
3. 拖門檻：看黃點在 ROC 曲線上移動（每個門檻一個點）。
4. 讀 AUC 公式與 TPR／FPR 公式。

**要能說出來**
- 語意 θ̄ 是「該狀態的平均好壞」，軌跡分數是路徑上 θ̄ 的平均，低於門檻就判異常。
- 優勢：能指出「從哪個 token 開始壞掉」，不只是「這個答案不好」。
- AUC = 隨機抽一個正常、一個異常，正常分數較高的機率；0.5 是擲硬幣。

**過關檢查**：能講清楚「門檻高 → 抓到更多異常，但誤判更多正常」，並指到 ROC 上的位置。

**讀**

- 整理 §10（RQ1～RQ3 與實務指引）、§9（AUC、Pearson、Kendall）。

**操作**
1. 觀念頁「數學與 12 個指標」（08 節有連結）：先看 3 條核心公式，再切換兩個分頁（抽象模型層級 6 個、語意層級 6 個）。**較暗、虛線的卡片**是主頁裡有即時數字的公式（標籤寫著在哪一節），先把這幾個講熟。注意：12 個指標的公式是依論文正文描述重建的，附錄 A 沒公開。
2. 網頁 07 論文實驗結果：切換「ROC AUC 範圍」與「RQ1 顯著比例」，看 10 個任務的 AUC 範圍；右邊卡片是 RQ1～RQ3 與限制。
3. 網頁 08 開頭的「表 III：超參數組合」：講得出每一列的乘法怎麼來、Grid 為什麼只能用 3～10 維。
4. 網頁 08 180 種設定空間（設定探索器）：x 軸換成不同指標、任務換 OOD-L 和 HE-C，看 Pearson r 的變化；勾掉 DTMC／HMM、Grid／GMM／KMeans 看前 5 名怎麼變。
   - **注意資料是真實的**，來自作者公開的結果，不是模擬（ADV-A 除外）。

**每條公式準備一句話（作用）**

| 指標 | 一句話 |
|---|---|
| SUC | 抽象後的狀態數比原本少多少（越小越精簡） |
| COV | 測試時有多少狀態是訓練沒見過的（越小越好） |
| SEN | 輕微擾動後狀態會不會跳掉（越小越穩） |
| SS | 有多少狀態進去就出不來（sink） |
| SDE | 模型是死板還是亂跳，離兩個極端的中點越近越好 |
| PERP | 對訓練分布擬合得多好 |
| PRE | 抽象後語意失真多少（與 AUC 相關最強） |
| ENT、IVT、NVT、NDT、SL | 語意曲線的隨機性、接近目標值的程度、上升下降的趨勢、意外程度 |

**要能說出來**
- 180 種設定從何而來（27 + 81 + 18 + 54），怎麼在沒有異常標註時用指標挑設定。
- PRE 與 AUC 強相關（Pearson 0.81～1.00）；PERP 是最廣用的模型層級指標；DTMC ≥ HMM，前 5 名全是 DTMC。
- **誠實面**：多數設定的平均 AUC 只有 0.55～0.70，最亮眼的 0.90（HumanEval）是 180 種裡最好的一個。

**過關檢查**：隨機指一個指標，5 秒內說出它量什麼、方向是高好還是低好。

**一定要講清楚的限制**
- 這是「同一套流程的縮小版示範」（GPT-2 small、CPU），不是事實查核器。兩個任務是分開的模型，各自用驗證集挑版本，測試集分數只報告、不拿來挑。
- **合理性（OOD）**：TruthfulQA 標準答案（正常）對自己打亂的版本（不是論文的資料）。採用「所有區塊串接」版（PCA 2048、KMeans 600 狀態）：驗證 0.87、測試 **0.91**（158 題）；只取最後一層版（PCA 96、200 狀態）為 0.79／0.83。
- **真實性（幻覺）**：現在評的是 **GPT-2 自己回答 TruthfulQA 的答案**，由 Gemini 判真假（論文用 GPT-judge），流程照作者程式碼。採用「所有區塊串接」版（PCA 2048、600 狀態）：驗證 0.77、測試 **0.65**；只取最後一層版（PCA 384、600 狀態）為 0.75／0.66。測試集只有 164 題（51 真、113 假），驗證與測試差了 0.12，數字不穩。量級接近論文 TQA-A 的平均 0.67，但模型、評審都不同，不能直接比。
- 為什麼有兩個版本：論文說每個 token 是「32 個區塊 × 4,096」，但沒說各層怎麼組合；作者程式碼只取最後一層。所以兩種都做並列出分數。
- **資料來源要分清楚**：
  - 自己的 GPT-2 實跑：03 劃分探索器、05 軌跡檢視器、06 分數分布與 ROC、09 實作。
  - 論文表格：07。作者公開的真實結果：08（ADV-A 除外，仍是模擬）。
  - 模擬：04 轉移模型建構器、05 的動畫；04 的動畫狀態是真實的、轉移是模擬的。

## 附錄 A：一分鐘講稿骨架

1. **問題**：LLM 會幻覺、會被對抗攻擊、遇到沒見過的輸入會出錯，但它內部太大（論文說 Llama-7b 每個字的隱藏狀態有 131,072 個數字）看不懂。
2. **方法**：LUNA 把每個字的隱藏狀態壓成少數抽象狀態，建成一個機率狀態機（DTMC），再把「好不好」的分數貼到狀態上。
3. **偵測**：一個答案變成一條狀態路徑，取路徑上分數的平均，低於門檻就判異常，還能指出從哪個 token 開始壞掉。
4. **結果**：在 3 個模型、7 個資料集、180 種設定下，最佳 AUC 到 0.90，但多數設定只有 0.55～0.70，結果對設定很敏感。
5. **限制**：只適用開源（白箱）模型；模型與資料集的範圍有限。

## 附錄 B：可能被問的問題（回答方向）

| 問題 | 回答方向 |

| 為什麼要抽象？ | 隱藏狀態太大（論文說 Llama-7b 為 131,072 維／token；作者程式碼實際取最後一層 4096 維），降維加分群後才能建小而可解釋的模型（03 節） |

| 為什麼用 DTMC 不用 HMM？ | 論文結果 DTMC 多數指標較好、前 5 名全是 DTMC；作者推測 HMM 是兩層抽象造成落後 |
| OOD 和幻覺的語意有什麼不同？ | 幻覺綁在狀態（真實性）；OOD 和對抗綁在轉移（轉移機率）（整理 §5.4） |
| AUC 0.9 代表什麼？ | 隨機抽一正一負，正常分數較高的機率是 90%；但這是最佳設定，不是平均 |
| 哪個指標最有用？ | PRE 與 AUC 相關最強且最一致；PERP 是最廣用的模型層級指標；其他指標跨任務會變號 |
| 你的實作可靠嗎？ | OOD 可以（測試 AUC 0.91）；幻覺偏弱（測試 0.65，驗證 0.77，164 題樣本小），是縮小版示範，模型和評審都和論文不同，不能直接比 |
| 為什麼不用論文的模型？ | 論文沒公開逐 token 隱藏狀態，要重跑 7B 模型在筆電上不實際；03、05、06、09 用自己的 GPT-2 實跑同一套流程，08 用的是作者公開的真實結果 |
| 這個方法的缺點？ | 只能用開源白箱模型；只測 3 個模型；結果對設定敏感、需要調參 |
| 跟 SAPLMA、ITI 差在哪？ | LUNA 多面向、可逐 token 線上監控；SAPLMA 是結束後分類；ITI 是推論時介入（整理 §7.3） |
